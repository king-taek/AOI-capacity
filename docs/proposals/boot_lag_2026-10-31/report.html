  • 손을 가장 적게 대려면 → V6 최소 변경(4줄 치환: 입자 8,000 · dpr 1 · 30fps 상한 · blur 제거). 콜백은 가벼워지지만 움직임이 30fps 라 덜 매끄럽다 — 임시 조치.
  • 렉을 원천 차단하려면 → V5 스캔 라인 · V3 CSS 스켈레톤 · 글자 T1~T3. 프레임마다 도는 JS 가 0 이라 어떤 PC 에서도 끊길 거리가 없다(합성기 드롭 32~114 vs 현재 273). 대신 '입자' 디자인을 버린다 — 현택 선택 사항.
  • 어느 안을 고르든 걷힘의 blur(5px) 는 뺀다. 전체 화면 흐림이 걷히는 순간 메인 스레드가 가장 바쁜 때와 겹친다 — blur 만 뺀 실행(noblur)에서 걷힘 구간 p95 108 → 48ms.

왜 렉이 걸리나 — 현재 코드 진단

  • 프레임마다 하는 일이 너무 많다. 입자 16,000개 × curl noise(noise 4번) = 프레임당 noise 약 64,000번 + Path2D 에 꼬리 선 16,000개 · 네모 16,000개를 넣고 팔레트(최대 40색)마다 stroke/fill. 실측 콜백 p50 3.1ms · p95 16.9ms — JS 만으로 예산(16.7ms)의 절반이고, 래스터(선 16,000개를 alpha 로 긋기)는 그 뒤에 따로 든다.
  • dpr 2 까지 그린다. 125~150% 배율 노트북이면 픽셀이 1.6~2.3배 — 같은 코드가 dpr 1.5 에서 12fps 로 떨어진다(기본 34fps, 최저 16).
  • Worker 라도 CPU 는 나눠 쓴다. 메인 스레드가 19MB JSON 을 해석하는 4~5초 동안 코어 하나를 다 쓰고, 래스터 스레드 · 합성기 · Worker 가 나머지를 나눈다. 4코어 계측기에서 현재 코드의 Worker 는 그 구간에 16~34fps 였다(실행마다 편차 큼 = 경쟁 상태의 특징).
  • 걷힐 때 전체 화면 blur(5px) + scale. 1920×1080(×dpr²) 캔버스 한 장에 필터를 0.5초 동안 — 그 순간 메인 스레드는 첫 화면을 그리느라 가장 바쁘다. blur 만 뺀 실행에서 걷힘 구간 메인 프레임 p95 108 → 48ms.
  • OffscreenCanvas 가 없는 브라우저(옛 Edge)는 전부 메인 스레드. 그땐 JSON 해석 동안 0프레임이다(현재 코드의 폴백 경로).

진단 기준: animation-performance 스킬(합성 전용 속성 · 메인 스레드 밖 · 프레임 예산) · improve-animations 감사 항목 5(성능) · design-motion-principles 생성 체크(blur 상한 · 바깥 이징 · 반복 맥동 금지).

어떻게 쟀나

  • 대상 파일: 30일치 보관 샘플(Report 55,717개)을 현재 template 에 넣은 19.3MB 결과 HTML — 현장에서 여는 크기와 같다. boot 스크립트만 변형별로 교체.
  • 브라우저: Playwright Chromium 153(헤드리스, 소프트웨어 합성) · Linux 4 vCPU. 조건 셋 — 기본(1920×1080 · dpr 1) · CPU 4배 느리게(CDP 스로틀, 메인 스레드만) · dpr 1.5. 기준 · 주요 변형은 2~3회 반복(표의 n).
  • 지표: ① 그림 스레드(Worker) rAF 간격 — 실제로 화면이 바뀐 간격(p95 · fps) 과 콜백 안 시간(JS + 캔버스 명령) ② 합성기가 '놓쳤다' 고 보고한 프레임(CDP 트레이스 PipelineReporter STATE_DROPPED) ③ 걷힘 구간(덮개 opacity 0 → 제거)의 메인 스레드 rAF 간격 p95 ④ long-animation-frame 합(메인이 막힌 시간 — 변형과 무관하게 4초 안팎, JSON 해석 · 모델 계산).
  • 주의: 헤드리스 소프트웨어 합성이라 절대값은 현장 PC(Windows · 내장 GPU) 와 다르다 — 변형 사이의 상대 비교로 읽는다. 합성기 드롭 수는 메인 스레드 레이어 트리 기준이라 Worker 캔버스 변형에서는 메인이 막힌 동안의 드롭이 섞인다(그 동안에도 캔버스는 Worker fps 로 움직였다). 현장 확인은 아래 '다음'.
