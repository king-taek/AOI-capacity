AOI 장비 가동률 대시보드를 이어서 만든다. 저장소는 `king-taek/AOI-capacity` 이고,
결과 화면(`aoi_capacity/ui/assets/template.html`)을 재설계한 상태다.

먼저 이 파일들을 읽어라.
1. `HANDOFF.md` — 전체 맥락
2. `RULES.md` — 화면이 따르는 계산 규칙. **임의로 바꾸지 마라.** 사용자와 확정한 것이다
3. `CHANGELOG.md` — 지금까지의 요청과 반영 내역
4. `app/AOI-Dashboard.dc.html` — 본체

제약:
- 결과 HTML 은 외부 요청 0, 단일 파일로 동작해야 한다. 웹폰트·CDN 금지, 시스템 폰트만
- 라이트 단일 테마. 다크 모드 없음
- 색은 의미가 있을 때만. 가동=파랑 계열, Error=빨강, Test=보라, 대기=회색
- 글자 수를 늘리지 마라. 설명문보다 숫자와 구조로 말한다
- NAS 는 읽기 전용

할 일 4가지, 순서대로.

**1. Error 상세 팝업 연결**
`app/Err-Popup-A.dc.html` 이 승인된 시안이다. 지금 Error 탭에서 장비 줄을 누르면
가동률 팝업이 뜨는데, 이 Error 분석 팝업이 뜨도록 바꿔라. 모든 장비·Job 에 공통 적용한다.
구성: 요약 5칸 → 발생 시각 타임라인(Error 진한 빨강, 그 뒤 대기 연한 빨강) →
유형별 막대 → 최근 21일 그 장비 Error 추이 → Lot별 목록(원문 전문).
우측 상단에 `가동률 보기` 버튼을 둬서 기존 팝업으로 넘어갈 수 있게 한다.

**2. TB500 · Kendall 리포트 탭**
상단에 `리포트` 탭을 하나 더 만든다. 대상은 표기명을 붙인 21개 Job 만(`RULES.md` 의 JOB_ALIAS).
이름순 정렬. 기간은 기본 31일, 버튼으로 최근 7·21일.
각 줄에: `준비 18.6 ± 2.1분` · `장당 8.11 ± 0.4분` · 최빈 장수 기준 환산 시간 ·
배치 수 · Error 건수 · Error 대기 시간 · **평균 fault(빈칸, "수집 예정")**.
Job 을 펼치면 같은 항목을 장비별로.
계산: 배치시간 = 준비시간 + 장당시간 × 장수 로 1차 회귀. 절편이 준비, 기울기가 장당.
표본에서 제외: Error 난 배치 · 중단된 배치 · 5장 미만 배치 (Test Lot 은 포함).
오차는 회귀 표준오차로 ± 를 낸다.

**3. 수집기 수정 — 백업 폴더 조회**
`patch/collector-backup-lookup.md` 의 안을 `aoi_capacity/devices.py` · `collect.py` 에 적용한다.
30대 검증 결과 읽을 수 있는 `WaferInfo.ini` 가 24,050 → 53,069 개(2.2배)로 늘어난다.
적용 후 `python -m aoi_capacity.cli --full` 로 재수집하고, 장비별 시각 확인 비율이
얼마나 올랐는지 확인한다(현재 AOI-4 4% · 4F-AOI-01 15% · AOI-7 43% · AOI-5 53%).

**4. faults 열 내보내기**
`collect.py` 의 내보낼 열 목록에 `faults` 를 추가한다(가능하면 `scanned_dice` · `yield` 도).
지금 결과 HTML 에 이 열이 없어서 리포트의 평균 fault 를 채울 수 없다.

작업 전에 모르는 것이 있으면 추측하지 말고 물어라. 특히 계산 규칙을 바꿔야 할 것 같으면
반드시 확인부터 받아라.

## 실제 제품에 옮길 때

지금 화면은 DC(Design Component) 형식이라 `support.js` 런타임에 의존합니다.
`template.html` 에 이식할 때는:
- 마크업·인라인 스타일은 그대로 옮길 수 있습니다
- `renderVals()` 의 계산 로직을 template.html 의 렌더 함수로 옮깁니다
- 데이터는 `aoi-data.json` 대신 `__DATA__` 자리에 박히는 embedded JSON 을 씁니다
  (열 구성이 다릅니다 — `RULES.md` 의 '데이터 출처' 참고)
