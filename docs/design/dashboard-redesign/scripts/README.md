# aoi-data.json 을 만드는 스크립트

`docs/design/dashboard-redesign/` 의 handoff 에서 빠져 있던 것들입니다.

## 먼저 알아두실 것

**파이썬이 아니라 JavaScript 입니다.** 이 프로젝트에서는 브라우저 샌드박스에서 돌렸기 때문에
`.py` 가 아니라 `.js` 입니다. 요청하신 `python make_aoi_data.py ...` 형태가 아니라
`node make_aoi_data.js ...` 가 됩니다. 로직은 그대로이니 이식하실 때 참고하세요.

**코드는 손대지 않았습니다.** 각 파일의 `[원본]` 블록은 실제로 돌린 코드 그대로입니다.
원래는 파일이 아니라 샌드박스 스크립트여서 `readFile` / `saveFile` / `log` 를 환경이 제공했는데,
Node 에서 돌아가도록 그 세 개만 파일 맨 위에 끼워 넣었습니다. 그 부분은 `(새로 추가한 부분)`
이라고 표시해 뒀고, 그 아래는 한 글자도 고치지 않았습니다.

**재현 확인했습니다.** 이 폴더의 `make_aoi_data.js` 본문을 그대로 돌려 나온 결과가
지금 `app/aoi-data.json` 과 **바이트 단위로 완전히 일치**합니다(2,246,732 bytes).

## 파일 목록

| 파일 | 무엇을 만드나 |
|---|---|
| `make_aoi_data.js` | `AOI_capacity 3.html` → `aoi-data.json`. **본체** |
| `job_alias.js` | 화면 표기명 21개. 데이터가 아니라 대시보드에 들어가는 표 |
| `build_offline.js` | `aoi-data.json` → `aoi-data.js`, 대시보드 → 오프라인용 소스 |

부속 파일은 없습니다. Job 병합 규칙 · Lot 이름 정리 규칙 · 사용자 override 는
**전부 `make_aoi_data.js` 안에 인라인**으로 들어 있습니다. 설정 JSON 도 없습니다.
찾으실 위치는 아래 '규칙이 코드 어디에 있나' 참고.

## 실행 방법

```bash
# 1. 데이터 만들기 (Node 18 이상, 외부 의존성 없음)
node make_aoi_data.js "AOI_capacity 3.html" aoi-data.json

# 2. 오프라인 빌드용 데이터·소스 만들기
#    (aoi-data.json 과 AOI-Dashboard.dc.html 이 같은 폴더에 있어야 합니다)
node build_offline.js
```

`make_aoi_data.js` 는 끝에 검증용 숫자를 찍습니다. 2026-09-19 16:16 수집본이면:

```
AOI-4 lots 32개 (배치 31) cv48% · Error Lot 4
AOI-8 lots 30
```

메모리를 20MB 입력 + 파싱된 배열만큼 씁니다. 기본 힙으로 충분하지만 더 큰 수집본이면
`node --max-old-space-size=4096 make_aoi_data.js ...` 로 여유를 주세요.

### 오프라인 단일 HTML

`build_offline.js` 까지가 스크립트고, 그 결과 `AOI-Dashboard-offline.dc.html` 을
한 파일로 인라인하는 마지막 단계는 이 프로젝트의 번들러가 했습니다
(런타임 `support.js` · `aoi-data.js` · 스타일을 HTML 안에 밀어 넣는 일).
저장소에서는 아무 인라이너나 쓰시면 됩니다. 조건은 두 가지입니다.

- 외부 요청이 0 이 되어야 합니다(웹폰트 · CDN 금지, 시스템 폰트만)
- `aoi-data.js` 는 `window.AOI_DATA` 에 담기고, 대시보드 로직이
  `window.AOI_DATA` 가 생길 때까지 30ms 간격으로 기다립니다

## 없는 것 — 조사 스크립트 4개

**넘겨 드릴 수 없습니다.** 솔직히 말씀드리면, 그 4개는 파일로 저장한 적이 없습니다.
PowerShell 코드를 채팅에 적어 드리면 사장님이 복사해 실행하시고 결과 txt 만 올려 주시는
방식이었고, 그 대화가 길어지면서 원문이 제 쪽에 남아 있지 않습니다.

남아 있는 것은 **결과 txt 4개**뿐이고, 이미 handoff 에 들어가 있습니다.

| 조사 | 결과 파일 | 무엇을 셌나 |
|---|---|---|
| AOI-4 경로 확인 | `data/AOI4_경로확인.txt` | 예상 경로 vs 실제 폴더 구조 |
| 백업 폴더 조사 | `data/Scanresult_백업조사.txt` | 30대 `Scanresult*` 폴더 이름 · Job 폴더 수 · 수정시각 |
| 복구율 검수 | `data/백업복구_검수.txt` | 장비별 라이브/백업/못찾음 Lot 수, INI 수 |
| 못 찾은 것 분류 | `data/못찾은것_분류.txt` | 못 찾은 984건의 원인별 분류 |

지금 다시 쓰면 **재작성본**이지 원본이 아닙니다. 사장님이 "정리본은 규칙이 바뀌었는지 알 수 없다"고
하신 그 문제가 그대로 생깁니다. 필요하시면 재작성해 드리되 원본이 아니라고 분명히 표시하겠습니다.
다만 이 4개는 일회성 조사용이고 화면 갱신에는 쓰이지 않으므로, 없어도 새 수집 결과로
데이터를 다시 만드는 데는 지장이 없습니다.

`make_aoi_data.js` 의 중간 버전도 파일로 남은 것이 없습니다. 무엇이 어떤 순서로 바뀌었는지는
`CHANGELOG.md` 에 정리해 두었습니다(Error 를 Lot 단위로 바꾼 것, 재스캔 판정을 뒤집은 것,
대기 시간 중복 계산을 고친 것, 배치 시각 열 `ba`/`bb` 를 넣은 것 순서).

## 규칙이 코드 어디에 있나

`make_aoi_data.js` 안의 위치입니다.

| 규칙 | 위치 |
|---|---|
| 시각 문자열 파싱 (`18-Sep-26` · `9/18/2026`) | `function P(s)` |
| Lot 이름 추출 | `R1` · `R2` 정규식, `KEEP` · `DROPW` 집합, `function lotName` |
| Job 병합 키 | `function jobKey` |
| 사용자 직접 지정 병합 | `const JM` — 지금은 `RKENDALLPI4DG → RKENDALLA0PI4` 한 줄뿐 |
| Error 유형 분류 | `const CR` (`collect.py` 의 `CAUSE_RULES` 와 같아야 함) |
| 자재 동일성 (중복·재스캔) | `const RT`, `const matKey`, 그 아래 `seen` 루프 |
| 구간 병합 · 시간 합산 | `function dayStats` |
| Error 대기 시간 배분 | `dayStats` 안의 `give` · `stop` 루프 |
| 시각 확인 비율 `cv` · 배치 구간 `bseg`/`be` | 파일 끝 `/* cv · bseg · be */` 블록 |

## RULES.md 와 코드가 다른 곳

읽으실 때 헷갈릴 만한 곳만 적습니다. **코드가 최신이고 실제 동작입니다.**

1. **구간 병합 간격이 두 개입니다.** RULES.md 에는 "8분 이하 틈은 이어 붙인다"고만 적었는데,
   실제로는 두 단계입니다. 데이터 만들 때 **3분**(`dayStats` 의 `g.a-L.b<=3`),
   화면에 그릴 때 추가로 **8분**(대시보드 `segsOf`). 수치 계산은 3분 기준이고,
   8분은 막대를 매끄럽게 보이게 하는 용도라 숫자에 영향이 없습니다.

2. **표기명 21개(JOB_ALIAS)는 데이터에 없습니다.** `aoi-data.json` 에는 실제 Job 이름만 들어가고,
   표기명은 대시보드가 화면에서만 씌웁니다(`job_alias.js` 참고). 그래서 표기명을 고쳐도
   데이터를 다시 만들 필요가 없습니다. RULES.md 만 보면 데이터 쪽 규칙처럼 읽힙니다.

3. **추정 판정(50%)도 데이터에 없습니다.** 데이터는 `cv`(시각 확인 비율)와 `be`(배치 점유 분)만
   담고, 추정 여부는 대시보드가 정합니다 —
   `isEst(t) = (cv < 50 || 측정값이 0) && be > 0`.
   RULES.md 에는 "50% 미만"만 적혀 있는데, 실제로는 **측정값이 아예 0 인 날도** 추정으로 넘어가고,
   **배치 시각조차 없으면(`be===0`) 추정하지 않습니다**(그 날은 `—`).

4. **`RE` 토큰이 양쪽에 있습니다.** Lot 이름을 만들 때는 남기고(`KEEP`),
   자재가 같은지 비교할 때는 뗍니다(`RT`). 의도한 것입니다 —
   화면에는 `KPW-SRD` 로 보이고, 중복 판정에서는 `KPW` 와 같은 자재로 봅니다.

5. **Test 판정은 정리 전 원본 Lot 문자열 기준**입니다(`/TEST/i.test(rl)`).
   `lotName()` 으로 정리한 이름이 아니라 Report 안의 Lot 칸을 봅니다.

6. **기준 날짜가 하드코딩되어 있습니다.** 출력 JSON 의 `day:'2026-09-18'` — 화면이 처음 띄울
   날짜입니다. 새 수집본에서는 바꾸셔야 합니다(`days` 배열의 마지막에서 하루 전쯤이 적당).

7. **`faults` 는 입력에 없습니다.** 수집 결과 HTML 의 열 목록에 `faults` · `scanned_dice` · `yield`
   가 빠져 있어서 스크립트도 읽지 못합니다. `collect.py` 의 내보낼 열에 추가하고 재수집해야
   리포트 탭의 평균 fault 를 채울 수 있습니다.

## 제품 이식 시 (사장님이 정하신 경계)

- **디자인 규칙으로 채택** — 추정 · Lot 단위 Error · 재스캔 정의 · Job 병합 · Lot 이름 ·
  라이트 테마 · 용어
- **제품 규칙 유지** — Error 후 대기 상한, 하루 분모

이 스크립트에서 해당하는 상수는 두 개입니다. 제품 값으로 바꾸세요.

```js
// dayStats() 안
if(gap>240) gap=240;        // Error 후 대기 상한 (분)
const mm=t=>Math.max(0,Math.min(1440,...))   // 하루 분모 (분)
```
