# 진행 내역 — 요청과 반영

시간순입니다. 각 항목은 사용자의 요청과 그에 대한 반영입니다.

## 1. 재설계 방향 정하기

- 사전 질문으로 확인: 정보 위계 없음 · 촌스러운 색 · 빽빽함 · 차트 안 읽힘 · 표 과다 · 어려운 용어가 문제.
  사무실/노트북, **라이트 우선**, 정보구조부터 전면 재편, 시안 비교 희망
- "처음엔 중요한 정보만, 클릭으로 점점 더. 지금은 글자가 너무 많고 가동률 bar 가 읽기 어렵다.
  **다크모드는 없애줘**"
- 홈 화면 시안 3종 제작(타임라인 보드 / 카드+고정패널 / 브리핑) → **A(타임라인 보드) 선택**
- 막대는 **중복스캔 · Test 까지 다시 넣기**로 6단계

## 2. 통합 대시보드

- A 방향으로 가동률 · 장비 상세 · Error · 추이 4화면을 한 파일에 구성
- 검수 지적 반영: 평균/증감 기준 통일, 축 라벨 잘림, 대비 4.5:1, 빈 타일, 히트맵 결측 인코딩,
  **같은 지표가 화면마다 다른 값** → 단일 집계 함수로 통일

## 3. 표현 정리

- "원인" → **"유형"**, 유형명은 **영문 원문 그대로**
- "Error 사건" → **"Error"**
- Wafer ID 는 화면에서 빼고 **Lot 으로 묶기**
- '먼저 볼 장비' 섹션 삭제, '장비별 하루' → **'오늘의 가동률'**
- 쓸모없는 설명문 일괄 삭제(막대 안내 · 헤드라인 · 어제 대비 · 가동률 공식)
- '살펴볼 순' 정렬 삭제, 기본 **번호순**
- **2층 / 4층 / 전체** 필터 추가
- **모든 컨트롤을 실제로 동작하게** (날짜 이동 · 필터 · 드릴다운)
- 돌아감 → **Scan**, 중복·재스캔 → **Rescan**, 안 돌림 → **대기**, 에러 후 대기는 **Error 에 통합**
- 색 범례를 표 **맨 위**로

## 4. 장비 상세 팝업

- 페이지 이동이 아니라 **팝업**으로
- Lot 을 세로 목록이 아니라 **24시간 막대 + 지시선 주석**으로. 이름표가 겹치지 않게 층층이 배치
- 막대의 세로 구분선 제거, **매끄럽게**. Lot 별 클릭 가능
- 지시선은 **막대 중앙(가로)** 에서 시작
- Scan 과 Error 가 섞인 Lot 은 지시선 점을 **Error 가 난 지점**에 (정상 구간 중앙은 어색)
- 막대에 **Lot 구별 테두리**
- 지시선이 이름표 **상단 중앙**에 도착

## 5. Error 분석

- 유형별 건수뿐 아니라 **그 Error 로 장비를 세운 시간**도
- 유형을 누르면 **히스토그램 + 표** 팝업
- 대기 시간 중복 계산 수정(시각 미기록 Error 가 같은 공백을 각자 가져가던 문제)
- Error 탭 기본은 **위에서 고른 날짜**
- "멈춘 시간" → **"대기 시간"**
- 기간 버튼에 **일자별** 추가. 일자별일 때는 기간 버튼이 모두 비선택
- **Job별 통계** 추가 (유형별 · 장비별 옆)
- Job별은 **Error 건수 순** + `Lot 14개 중 8개 Error` 표기
- 건수/대기시간 토글이 Job별에도 적용, 선택한 지표가 **굵게**
- 일자별로 볼 때는 날짜별 차트를 감추고, 기간으로 볼 때만 표시 + 부드러운 등장 애니메이션

## 6. Job · Lot 이름 정리

- Report 파일명에서 Lot 을 뽑는 규칙 확정(질문 6라운드)
- Job 병합 규칙 확정 — R접두어는 구분, 표기는 실제 이름, **통계에서만 병합**
- 중복 판정에 **Job 포함** (Lot 이름만 같아서는 중복이 아님)
- 재스캔 재정의 — 앞선 시도가 Error 면 정상 Scan, Pass 였으면 Rescan
- Scan 많은 순 상위 30개를 보고 **표기명 21개** 확정
- `Kendall PI4` 와 `PI4 DG` 는 같은 것으로 병합(근거: AOI-25 한 대에서 날짜가 갈림)

## 7. AOI-4 데이터 이상 조사

- "AOI-4 는 왜 데이터가 이상하지?" → 7,746행 중 시각 있는 행 316개(4.1%)
- 1차 조사: 경로 규칙 문제가 아니라 **INI 가 없음** (`MoveResultFlag` 만 남은 폴더, Lot 폴더 자체 삭제)
- 사용자 제보: **백업 폴더가 있다** (`Scanresult_Back up_260918`)
- 2차 조사: 30대 중 16대에 백업, Job 폴더 5,078개가 잠겨 있음. 이름 규칙 제각각
- 사용자 제보: **어느 날짜 기준 그 이전을 통째로 백업** → 배치 날짜로 폴더를 바로 고를 수 있음
- 3차 조사(복구율): 검사 4,107 Lot 중 1,840(44.8%)이 백업에서 발견.
  읽을 수 있는 INI **24,050 → 53,069 (2.2배)**
- 4차 조사(못 찾은 것): 984건 중 731건은 **검수 스크립트의 파싱 오류**.
  실제 결손은 **75건(2.7%)**. 반증 — 못찾음 100% 로 나온 AOI-21·22·24·25 가 실제로는 66~79% 읽힘
- 결론: 2.7% 는 감수하고 **배치 시각 추정**으로 메우기로 결정

## 검수에서 잡혀 고친 것들 (참고)

같은 실수를 반복하지 않도록 남깁니다.

- 같은 지표를 두 곳에서 다르게 집계 → 단일 함수로 통일 (2회 발생)
- 4.5:1 미만 텍스트 → 보조색을 `#5A6673` 하나로 통일. **배경이 흰색이 아닌 곳도 확인할 것**
- `flex-grow` 때문에 마지막 칸이 한 줄을 차지 → `grid` + `auto-fit`
- 목록을 조용히 잘라 놓고 헤더에는 전체 숫자 → 자르면 자른다고 밝히기
- 안내문과 실제 표시가 반대 (`대기 시간은 낼 수 없습니다` 라면서 대기 시간 표시)
- 데이터 로드 전 분기에 키 누락 → 미해결 홀 경고
- `\b` 단어 경계가 `_` 앞에서 안 걸려 `LIVE_` 치환 실패 → 토큰 단위로 처리
- 선언 전 참조(TDZ)로 렌더 전체가 죽음
