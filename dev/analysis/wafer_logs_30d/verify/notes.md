## What was checked

1. **Time decomposition / G5 share.** Reproduced gen_share exactly (G5 58.0%, load 1,045 h + post 957 h = 2,002 h). Then tested what ScanLog `Duration` covers on 2-recipe wafers using the ExtendedScanMetaData timestamps (ext[recipe] = that recipe's scan start; scanstart == ext[first] on 100% of wafers). Raw bundle check (AOI-23 GDN-RDL3, 52215757EWF2): single `[2D]` section, Duration 565.8 s; x20 segment (x20 start → x5 start) 580 s; x5 segment 136 s. For RDL 94% of 6,234 multi wafers have dur ≈ x20 segment (ratio 0.85–1.0). So Duration = first recipe only; the second recipe's scan lands in "post". Re-attributing seg2 − 20 s to scan: G5 scan share 58% → 75.3%, non-scan overhead 2,002 h → ~1,180 h (load 1,045 + switch 125 + post ≈ 10). Other gens: EagleT 72.8 → 81.9%, EagleTP 76.2 → 77.6%, EAGLE unchanged. G5 load 66 s vs 15–17 s under CR≠Wafer & AF=None is confirmed; AF=Wafer pushes G5 load to 86 s.
2. **Multi-scan post.** True x5 scan from 104 single-x5 wafers: 55 s. Multi "post" 110–160 s = x5 55 s + switch (seg1 − dur) 14–63 s + post2 (seg2 − 55) 24–66 s. Switch is machine-dependent with the same CR=Lot: AOI-19 14 s, AOI-20 16 s, AOI-23 23 s, AOI-24 58 s, AOI-25 5 s; with CR=Wafer it jumps to 108–113 s (AOI-23, AOI-25). Verdict: wrong as stated.
3. **CR=Wafer cost.** As-is 542 h reproduced. Matched same device+job+AF (≥10 wafers each side): 112 pairs, 15,857 wafers, 381 h, median delta +39 s. Dropping pairs where the x20/scan duration also moved >20% (recipe change confound: AOI-25 RDL2 +1,008 s load with scan 826 vs 582; AOI-15 BS UBM scan 231 vs 89; AOI-23 RDL3 +522 s): 193 h on 11,652 wafers → extrapolated to all 25,673 CR=Wafer wafers ≈ 425 h. Per-gen clean delta: EagleT +66, EagleTP +45, EAGLE +32, G5 +25 s. Report both.
4. **Repeat scans.** Reproduced 17,759 / 1,367 h and the class counts. Sub-classified the two "different lot name" classes (5,217 pairs, 664 h) by recipe change, TEST/No Pattern, whole-lot (≥20 wafers, ≥80% of lot) vs partial. Three buckets over all pairs: genuine re-inspection 4,010 (23%, 452 h); different inspection step/recipe 11,687 (66%, 538 h); test/monitor wafers 2,062 (12%, 377 h). "Different lot name" is only ~48% genuine. RE-marked reruns: 94% had first status Pass → genuine.
5. **Idle.** Reproduced 62.0% (span-based), 8,273 h gaps, 54.4% < 2 h. Fixed common window (9/9 00:00 → 10/10 04:28, 748 h): 60.2% busy, 22,454 device-h, 13,523 busy-h; 658 h before-first/after-last batch is outside the gap total. Only AOI-20 differs materially between the two bases (77.9 vs 67.6).
6. **Rows without own INI.** The 14,321 figure counted (rows − INIs) only in multi-report lots and included never-scanned rows. Using Report `Wafers Scanned`: 137,621 rows; 15,396 (11.2%) lack INI = 7,777 (5.7%) never scanned (aborted runs) + 8,427 (6.1%) scanned but no INI in that report's window (overwritten or unrecorded). 22.9% multi-report lots confirmed.
7. **Review.** Median 3.8 h confirmed; unreviewed 30.6% → 30.1% excluding last 3 days (censoring negligible). 100% of 0-defect wafers (19,367) are unreviewed; among wafers with ≥1 defect 17.7% unreviewed, 100+ defects 45.2%. Of wafers older than 3 days, 62.5% reviewed within 24 h, 65.9% within 72 h — flat afterwards. G5 TB500 family medians 7–25 h, RDL2 153 h.
8. **AOI-17 Enhanced.** Confirmed 703–827 s (PI4 Enh 10/8: 1,062) vs 203–305 s elsewhere. Both recipe segments ~2.5× slower (seg1 437–561 vs 160–325; seg2 ~381 vs 117–171), dies identical (30), AOI-17's plain PI2/3/4 normal (241–259 s). params4: AOI-17 is the odd one on 93 keys (Zwafer focus offset ≈ −20 vs ~0, GMF alignment params, UseFastCCSFocusMapping=0, 28 detection keys) — no single culprit identifiable from files.

## Surprises / caveats
- ScanLog `Duration` is first-recipe-only — this reshapes claims 1 and 2 and would also affect any "scan share" number for multi-recipe jobs in the product dashboard if it ever used ScanLog.
- For PI 2-recipe wafers dur/seg1 ≈ 1.16 (Duration slightly exceeds the first segment); the second recipe's ExtendedScanMetaData timestamp seems to be written while the first recipe is still finishing (no objective change, pipelined). Scan-share correction for PI therefore carries ±10–40 s/wafer uncertainty; RDL (objective switch 20x→5x) is clean.
- Single-recipe PI_Bubble runs (TB500 PI4, n=50) show Duration 41 s vs a 222 s first segment in multi context — not resolvable from these fields; left out of conclusions.
- Defect cap truncation is negligible (e.g., RDL2 53 of 4,671 recipe-results at cap). Not reported.
- Recipe-switch excess vs best machine totals only 57 h fleet-wide — real but small; folded into claim 2 rather than a headline.
